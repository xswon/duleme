## 3. P0：发布前必须解决

### P0-01 时间线信息架构与路由统一｜已完成

解决前问题：

- 生产左栏和移动底栏仍同时显示“今天”和“未读”。
- 页面标题仍使用“今天/未读”，与已确认的“时间线 + 仅看未读筛选”不一致。
- 路由仍把未读生成成 `/unread`，没有实现 `/today?unread=1` 及兼容跳转。
- 生产页面没有“全部 / 文章 / 播客”筛选、最近 30 天范围标签和时间线内的“仅看未读”控件。

验收条件：

- 桌面、收起细条、抽屉和移动端均删除独立未读入口，统一显示“时间线”。
- 时间线内提供内容类型和仅看未读筛选；刷新、前进和后退可恢复筛选。
- 默认筛选不写冗余查询参数；非默认状态使用 `unread=1`、`type=article|podcast`、`days=60|90|…`。
- 访问旧 `/unread` 时使用 replace 语义迁移到 `/today?unread=1`，不能在浏览器历史中形成往返循环。

完成结果：桌面与移动端已删除独立未读入口；时间线、订阅源和文件夹共用类型/未读筛选；`unread`、`type`、`days` 可通过 URL 恢复；旧链接已在浏览器中验证为 replace 迁移。

### P0-02 最近 30 个本地自然日的统一计算｜已完成

解决前问题：

- 生产实现以 `30 × 24 小时`作为滚动窗口，而产品规则是本地日期往前 29 天零点至当前时刻。
- 夏令时地区、跨时区和本地零点附近会出现计数与列表边界不一致。
- 计数和列表依赖 React 重新渲染；页面长时间打开且没有数据变化时，跨过本地零点不会自然更新。

验收条件：

- 计数、列表、历史剩余数和批量操作共用同一个自然日范围工具，不分别计算。
- 覆盖本地零点、夏令时切换、未来时间、无效日期及恰好位于边界的测试。
- 在下一个本地零点或页面重新获得可见性时重新计算范围，但不得修改文章本身的已读状态。
- 时间线、文件夹和单个订阅源的徽标均使用相同的最近 30 天口径，显示以 `99+` 封顶、无障碍标签保留精确数字。

完成结果：列表、未读数、历史剩余数及批量操作已统一使用本地自然日窗口；覆盖 DST、边界、未来和无效日期；跨午夜与页面重新可见时自动重算。

### P0-03 全局唯一音频状态与播放进度｜已完成

解决前问题：

- 文章详情和播放列表各自创建音频元素，播放列表没有接入应用层共享播放状态，存在两个音频同时播放的风险。
- 播放列表中的进度只保存在组件本地，没有写回 `audioProgressMap`；刷新页面后可能丢失本次进度。
- 生产播放列表仍是旧版大图播放器，没有倍速、统一错误状态和已确认的纵向布局。
- 文章详情播放器可能直接显示 RSS 的原始 duration 字符串，不能保证是 `42:16` 这类结束时间。

验收条件：

- 全应用只有一个音频控制器和一个实际播放实例；详情页、播放列表和队列行都是同一状态的受控视图。
- 切换入口不会叠加播放；正在播放、当前暂停项和右栏查看项可以分别识别。
- 进度节流持久化，并在暂停、切换、页面隐藏和卸载前补写；持久化失败提供可操作反馈。
- 播放列表实现已确认原型：封面居中、标题/来源位于下方、起止时间独占一层、三个主操作精确居中、倍速位于右侧、队列选中无左侧蓝边。
- 倍速在详情和播放列表间保持一致；结束时间使用媒体 metadata 的精确时长并统一格式化。
- 覆盖加载、播放拒绝、媒体错误、切换、播放结束、删除当前项、清空、恢复进度和倍速的测试。

完成结果：生产 DOM 仅保留一个音频实例；详情页与播放列表共享播放、进度、倍速和错误状态；进度按 5 秒节流并在关键生命周期补写；删除/清空当前项会安全停止；播放器布局已按定稿实现。

### P0-04 批量已读的数据一致性｜已完成

解决前问题：

- 当前实现逐条发起存储写入并立即提示成功，写入失败没有汇总、回滚或错误反馈。
- 大批量操作可能出现界面已读、持久化部分成功的分裂状态。

验收条件：

- 批量操作只处理当前已加载时间范围和当前筛选结果。
- 使用可确认结果的批量写入或事务；失败时回滚界面，或明确报告失败项并允许重试。
- 5 秒撤销同时覆盖内存与持久化；刷新页面后不能重新出现已提示成功但实际未保存的未读状态。
- 全历史标为已读只放在更多菜单并二次确认，不复用当前范围按钮。

完成结果：当前范围批量已读与撤销均使用 IndexedDB 单事务；失败会整体回滚并提示重试；重复点击由串行协调器拦截。

### P0-05 本机服务与代理安全边界｜已完成

解决前问题：

- Docker Compose 将端口发布到 `127.0.0.1`，但直接启动服务时监听 `0.0.0.0`；两种运行方式的“仅本机”承诺不一致。
- RSS、图片、音频和 AI 接口在服务可被局域网访问时没有统一的本机请求限制或鉴权。
- 外部 URL 检查主要基于字符串 IP，仍需覆盖 DNS 解析到私网、链路本地地址、IPv6/映射地址和重定向后的目标。
- 对缺失 `Content-Length` 的流式响应需要实际字节上限，不能只依赖响应头。

验收条件：

- 原生启动默认只监听 `127.0.0.1`；容器内部可监听 `0.0.0.0`，但宿主端口仍只发布到 `127.0.0.1`。
- 如果未来允许局域网访问，必须显式开启并增加鉴权、来源校验、速率限制和敏感接口保护。
- 每次跳转都重新验证解析后的目标地址；RSS、图片和音频均有超时及实际读取字节上限。
- 增加私网、IPv6、DNS 重绑定/重定向、超大和无长度响应的服务端测试。

完成结果：原生服务仅监听回环地址，Docker 仅向宿主回环地址发布端口；敏感 API 统一限制本机来源；外部请求逐跳校验 URL 与 DNS 结果，并具备连接/空闲超时、声明大小和实际字节双重限额。

## 4. P1：候选版本前完成

### P1-01 原型视觉和列表行为对齐

- 左栏收起保留 52px 细条已完成；候选版本继续验证不同桌面宽度下的稳定性。
- 左栏按时间线、收藏、音频、笔记、搜索连续排列；五项同为一级导航，不显示“工具”标题，不保留分组间距或收起态分隔线。音频、笔记、搜索位于订阅树之前；展开、52px 收起态和抽屉必须一致。
- 文件夹名称默认使用 400 字重；仅选中时使用与其他左栏选中项一致的蓝色和 700 字重。
- 左栏底部“设置”必须使用独立底部锚点，所有范围和工具页保持同一纵向坐标；只有中间导航区允许滚动。展开、收起、长订阅树和安全区均需验证。
- 中栏取消额外日期分组行，保留卡片内相对时间；补齐来源、未读点和音频时长元信息，并按定稿采用 40×40 缩略图与约 68–72px 单卡高度。
- 已读与未读的标题、摘要、来源、缩略图和透明度保持一致；只给未读项显示小蓝点。已读项不得保留蓝点占位，来源必须左移并与标题首字对齐。
- 列表末尾只显示灰色常规字重的“继续加载 30 天”，不显示历史未读数量。
- 音频与笔记中栏顶栏分别显示“音频 N 条”和“笔记 N 条”，内容区不重复分组名、大标题、数量或说明；右侧垃圾桶用于删除全部，列表为空时禁用，执行前二次确认。
- 搜索中栏顶栏不显示批量标为已读和排序按钮。
- 桌面列表标题/摘要按 15px/13px 对齐原型；右栏正文保持 16px、约 1.75 行高和 650px 版心。
- 文章标题、副标题、播放器、标签和正文共享同一左边界；文章容器顶部采用与左栏、中栏一致的 9px 起始轴。副标题来源与时间戳统一为 13px、灰色、400 字重，来源不加粗。
- 文章和播客详情首个标签统一为“正文”及相同图标。AI 摘要直接显示短精华，不显示“内容精华”标题；深度精华默认收起，由居中按钮展开。
- 全局图标使用一致的 Lucide 风格、描边和光学尺寸；左栏刷新及详情正文、AI 摘要、逐字稿、笔记 Tab 图标以 15px 可见尺寸为基准。逐字稿使用标准 `AudioLines` 音波竖线图标，点击热区不得随图标缩小。
- 桌面详情快捷操作按定稿固定在右栏顶栏右侧，使用横向五项胶囊；阅读设置面板从顶栏下方展开并与胶囊右边缘对齐。761–899px 单页模式沿用同一横向胶囊，且任何状态不得遮挡正文。

本轮原型定稿（2026-09-15）：以上导航、列表、工具页、详情摘要与图标规则均已写入静态原型；生产版尚需逐项实现并按本节验收，不得直接复制原型假数据或评审控件。

### P1-02 移动端导航与阅读

- 独立未读已移除；底部导航仍需调整为时间线、搜索、收藏、更多。
- 详情正文提高到 16–17px，并验证 390px、短屏、横屏、软键盘和安全区。
- 抽屉包含完整导航和设置；返回列表、浏览器返回、手势与焦点行为一致。

### P1-03 无障碍和键盘操作

- 播放进度支持方向键、Home 和 End；所有媒体按钮有动态名称和可见焦点。
- 桌面热区不少于 32px，移动主要操作不少于 44px。
- 弹窗和抽屉具备焦点约束，关闭后返回触发点；Escape 行为可预测。
- 小字号辅助文字、选中态和已读态通过 WCAG AA 对比度检查。

### P1-04 真实浏览器与数据规模验证

- 验证 URL 刷新、前进/后退、旧链接迁移和无效 ID 恢复。
- 在 390、760、899、900、1279、1280 和 1440px 验证布局。
- 逐项切换已选文章、空详情、订阅源、普通文章、音频、笔记、搜索和设置，记录侧栏底部按钮坐标；展开/收起边栏、抽屉及订阅树前后坐标应保持一致。
- 对照静态原型检查左栏连续一级导航、文件夹字重、已读来源对齐、音频/笔记标题数量与清空确认、搜索顶栏、详情副标题和 15px 图标光学尺寸。
- 验证详情顶栏横向胶囊在短窗口、窄右栏、长标题、滚动正文和阅读设置展开时均不遮挡内容，并验证单页模式布局。
- 使用至少 10,000/50,000 篇文章检查首次载入、筛选、未读计数、历史扩展和批量已读性能。
- 验证 OPML 部分成功、同步部分失败、图片失败、音频 Range、AI 失败和完整备份恢复。

## 5. 建议实施顺序

1. 在已完成 P0 基线上，先落实 P1-01 的左栏、列表、音频/笔记/搜索顶栏、详情摘要和图标规范，并补充针对性组件测试。
2. 对齐移动导航和详情排版，验证展开、收起、抽屉及各响应式断点。
3. 完成真实浏览器、无障碍、数据规模和失败场景验收后再生成候选版本。

## 6. 发布判定

- 任一 P0 未完成：不得发布。
- P0 全部完成、P1-01 至 P1-03 完成，且自动化与真实浏览器验收通过：可进入候选版本。
- 候选版本完成备份恢复和真实数据回归：方可发布生产版。
